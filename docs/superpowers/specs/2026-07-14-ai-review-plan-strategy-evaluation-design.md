# AI 复习规划策略与评测设计

日期：2026-07-14

## 目标

把当前“AI 规划”从一个前端可用闭环，升级为可解释、可验证、可迭代的后端规划策略。

核心原则是：先由后端按用户选择的规划模式筛出合适候选，再把压缩后的候选和约束交给 AI；AI 负责组织日程、解释理由和给出学习建议；后端再校验草案，只有用户勾选确认后才写入复习规划。

这不是让 AI 直接读取所有历史记录，也不是让五种模式共享同一套候选数据。五种模式必须“看人下菜碟”：

- 错题回收：优先处理错题、待核对、错题相关到期任务。
- 补弱优先：优先处理薄弱知识点及其关联错题，少量到期任务兜底。
- 新题启动：优先安排未开始、未掌握、基础题和起步候选。
- 均衡推进：混合错题、薄弱、新题、到期任务，避免单一类型塞满。
- 考前冲刺：优先到期、逾期、错题、薄弱、收藏未掌握，尽量少安排普通新题。

## 非目标

第一版不做这些事：

- 不让 AI 直接写入任务。
- 不让 AI 读取全量练习历史。
- 不建立大型数据库重构。
- 不替代现有复习规划任务按钮。
- 不把“未开始题”混入所有模式。
- 不把 AI 规划做成普通聊天窗口。

## 当前问题

当前前端已经有五种模式、纳入内容、天数和每日时长选择，也能生成草案并选择性加入复习规划。但后端目前更接近“把通用候选池和 goal 文本交给 AI”，五种模式没有足够明确的数据差异和硬约束。

这会导致：

- 选择“错题回收”时，可能仍混入普通新题。
- 选择“新题启动”时，无法很好处理冷启动和未开始题。
- 界面 Top-K 和 AI Top-K 容易混淆。
- 数据多以后，候选池可能过大或不稳定。
- 无法证明五种模式真的有语义差异。

## 数据分层

### 1. 原始记录层

保存用户真实历史，不直接喂给 AI：

- 每次练习单提交。
- 每题作答、判分、AI 判分、人工确认。
- 草稿和未提交练习。
- 复习任务状态变化。
- 用户收藏、错题、掌握状态、个人备注。

### 2. 聚合统计层

供页面和规划策略读取：

- 用户总览：练习数、题次数、正确数、错题数、待核对数、到期数、未提交练习数。
- 题目统计：练习次数、错误次数、待核对次数、连续错题、连续做对、未答次数、最近状态。
- 知识点统计：做过几次、错几次、待核对几次、未答几次、优先级、置信度。
- 任务统计：逾期、今日、未来、完成、取消。

### 3. 候选池层

这是给 AI 的主要输入，不是给用户直接看的全部内容。

候选池按模式构造，每个候选保留少量字段：

```text
id
type: weak_topic / wrong_question / pending_review / review_task / unstarted_question / draft_attempt / favorite_unmastered
title
subject
exam_type
source
topics
question_type
priority_score
reason_tags
due_at
last_practiced_at
attempt_count
wrong_count
pending_review_count
unanswered_count
estimated_minutes
```

### 4. AI 输入层

AI 输入只包含：

- 用户选择的模式、天数、每日时长、学科范围。
- 模式策略说明。
- 压缩后的候选池。
- 禁止项和硬约束。
- 输出 JSON schema。

不包含全量历史作答，不包含长解析，不包含完整题干，除非后续单独做“题目详情解释”。

## UI Top-K 与 AI Top-K

界面 Top-K 和 AI Top-K 必须不同。

界面 Top-K 是给用户看的，应该短、清楚、可行动：

- 薄弱知识点 Top 3 或 Top 5。
- 下一步建议 3-5 个。
- 错题池默认展示 Top 5，可展开。

AI Top-K 是给规划器统筹用的，应该更宽：

- 薄弱知识点 Top 20。
- 错题 Top 40。
- 待核对 Top 30。
- 到期/逾期/未来任务 Top 30。
- 未提交练习 Top 20。
- 未开始/未掌握题 Top 50。
- 收藏未掌握 Top 20。

AI Top-K 的上限还要受模式影响，不是所有模式都拿所有数据。

## 五种模式策略

### 均衡推进

适用场景：用户希望每天都有进度，不只盯错题。

候选配比：

```text
到期/逾期任务：10
错题：15
待核对：10
薄弱知识点：15
未开始/未掌握题：10
未提交练习：8
收藏未掌握：8
```

硬规则：

- 每天至少 2 类任务，除非候选不足。
- 错题和薄弱项不能占超过 70%。
- 未开始题不能超过 30%。
- 到期/逾期任务必须优先放在前两天。

### 补弱优先

适用场景：用户有明显薄弱知识点，需要集中修补。

候选配比：

```text
薄弱知识点：25
薄弱知识点关联错题：25
待核对：10
到期/逾期任务：8
未开始/未掌握题：5
收藏未掌握：8
```

硬规则：

- 每天至少围绕 1 个薄弱知识点。
- 同一天不要塞超过 3 个知识点。
- 如果某知识点置信度低，只能作为次级任务。
- 普通未开始题只允许作为补充，不作为主任务。

### 错题回收

适用场景：用户想把历史错题、待核对和反复错题处理掉。

候选配比：

```text
错题：40
待核对：20
错题相关到期/逾期任务：15
未提交错题练习：10
收藏且未掌握错题：10
```

默认排除：

- 普通未开始题。
- 普通新题。
- 与错题知识点无关的题。

硬规则：

- 计划主任务必须来自错题、待核对或错题相关任务。
- 若用户手动纳入未开始题，必须标记为“手动纳入”，且比例不超过 15%。
- 同一道错题不能在同一计划里重复出现。

### 新题启动

适用场景：用户几乎没开始，或者想启动新章节/新题库。

候选配比：

```text
未开始/未掌握题：60
基础知识点起步候选：20
收藏未掌握：10
到期/逾期任务：5
未提交练习：5
```

冷启动候选不叫“薄弱 Top-K”，而叫“起步候选”。来源包括：

- 用户选择的考试范围：数一、数二、数三、408、英语、政治。
- 题库结构顺序：年份、题型、章节、知识点。
- 基础知识点优先：极限、导数、积分、级数、线代基础等。
- 题型配比：选择题、填空题、解答题按真实试卷或用户设置分配。
- 用户偏好：从近年开始、从基础开始、从某知识点开始。

硬规则：

- 如果用户没有历史记录，不能生成“薄弱原因”，只能生成“起步理由”。
- 不把没有数据支持的知识点说成薄弱。
- 到期/逾期任务只做提醒，不压过新题启动。

### 考前冲刺

适用场景：临近考试或用户想短期提高得分稳定性。

候选配比：

```text
逾期/今日任务：20
错题：25
高优先级薄弱知识点：20
待核对：15
收藏未掌握：10
未提交练习：8
普通未开始题：2
```

硬规则：

- 普通新题默认不出现，除非错题/薄弱候选不足。
- 每天任务量要保守，避免过载。
- 优先安排高收益、短反馈任务，例如错题复盘、待核对、专项小练习。

## 模式与纳入内容的联动

“规划模式”和“纳入内容”需要联动。

模式决定默认允许范围，纳入内容只能在这个范围内做细调。

示例：

- 用户选择“错题回收”时，默认隐藏或禁用“未开始/未掌握题”。如果用户在高级设置里强行打开，前端需要提示“这会打破错题回收模式，作为手动纳入处理”。
- 用户选择“新题启动”时，默认打开“未开始/未掌握题”和“基础起步候选”，默认关闭“高频错题”。
- 用户选择“补弱优先”时，默认打开“薄弱知识点”和“关联错题”，未开始题只作为补充。
- 用户选择“考前冲刺”时，普通新题默认关闭，收藏未掌握、到期任务、错题默认打开。

后端不能只相信前端勾选，必须再次用 mode policy 校验。

## 候选排序策略

每类候选先内部排序，再由模式配比混合。

### 错题候选排序

```text
score =
  当前题优先级 * 0.35
+ 连续错题/最近错误 * 0.25
+ 错题次数平滑值 * 0.15
+ 关联薄弱知识点强度 * 0.15
+ 收藏/手动标记 * 0.05
+ 到期/逾期任务关联 * 0.05
```

### 待核对候选排序

```text
score =
  最近提交权重 * 0.30
+ 影响知识点优先级 * 0.25
+ 用户答案与参考答案差异风险 * 0.20
+ 题型权重 * 0.15
+ 关联错题/错题本 * 0.10
```

选择题原则上不进入待核对池，除非后端明确标记为 AI/人工冲突。

### 薄弱知识点排序

沿用当前优先级思想，但用于规划时要扩大候选：

```text
score =
  历史风险与数据置信度 * 0.45
+ 最近风险 * 0.15
+ 连续错题 * 0.10
+ 待核对 * 0.10
+ 跳题/未答 * 0.08
+ 收藏/手动标记 * 0.07
+ 真题频次/重要度 * 0.05
```

### 未开始题排序

```text
score =
  用户选择范围匹配 * 0.30
+ 基础知识点优先级 * 0.25
+ 题库结构顺序 * 0.20
+ 题型配比需求 * 0.15
+ 收藏/手动标记未掌握 * 0.10
```

## AI 输出约束

AI 必须输出 JSON，后端只接受结构化草案。

草案结构：

```json
{
  "title": "7 天数学复习计划",
  "mode": "wrong",
  "summary": "为什么这样安排",
  "items": [
    {
      "key": "stable-key",
      "title": "复习 2025 数一 Q2 错题",
      "target_type": "question",
      "target_id": "kaoyan_math1_2025_q002",
      "due_at": "2026-07-15",
      "estimated_minutes": 20,
      "reason": "最近连续做错，关联导数应用",
      "source_candidate_type": "wrong_question"
    }
  ],
  "warnings": []
}
```

后端校验：

- `target_id` 必须存在。
- `target_type` 必须合法。
- `due_at` 必须落在用户选择的日期范围内。
- 总时长不能明显超过用户每日时长。
- 模式禁止项不能混入。
- 同一目标不能重复安排。
- 不能写入空标题或问号标题。
- AI 声称的模型名不可信，显示实际调用模型。

## 评测目标

评测不是只看 AI 文案，而是看四件事：

1. 候选池是否符合模式。
2. 规划是否可执行。
3. 解释是否基于真实数据。
4. 写入复习规划后是否闭环。

## 指标

### 模式一致性

衡量草案是否符合用户选择的模式。

示例：错题回收模式里，错题/待核对/错题相关任务比例应 >= 85%。

### 禁止项违规率

衡量是否混入模式默认禁止的数据。

示例：错题回收模式混入普通未开始题就是违规。

### 高优先级覆盖率

衡量草案是否覆盖候选池前列任务。

示例：Top 10 错题至少覆盖 3-5 个，具体按计划天数和每日时长调整。

### 任务负载合理性

衡量每天任务时长是否接近用户设置。

目标：每天安排时长在用户设置的 70%-120% 内；考前冲刺可偏保守。

### 多样性

衡量均衡推进和补弱优先是否避免单一任务类型或单一知识点塞满。

### 冷启动合理性

无历史记录时，不应生成薄弱结论；应生成起步候选和范围内基础练习。

### 可执行性

每个任务都能落到真实题目、练习单、知识点或复习任务。

### 重复率

同一目标在同一个草案中不重复出现。

### 解释真实性

理由必须引用候选数据，例如“错 4 次”“最近待核对”“到期任务”，不能空泛。

### 写入成功率

用户勾选后，任务应能幂等写入复习规划。

## 参数化扩展画像

固定 60 个画像之外，再用参数组合生成扩展画像。

参数：

```text
practice_volume: 0 / 1 / 5 / 30 / 100 / 1000
accuracy_band: very_low / low / medium / high
pending_review_level: none / low / high
overdue_level: none / low / high
draft_level: none / low / high
unstarted_level: none / low / high
topic_concentration: single / multi / scattered
manual_state_level: none / favorites / wrong_book / unmastered
```

每轮评测至少：

- 固定 60 个画像全跑规则评测。
- 从参数化画像中抽样 40 个边界组合。
- 每个画像跑 5 种模式。

这样每轮至少有：

```text
(60 + 40) * 5 = 500 组规则/模拟评测
```

真实 AI 不需要全量跑，按代表性抽样。

## 评测流程

### 第一层：规则评测

检查候选池和 mode policy 是否正确。

目标：

- 五种模式的候选类型差异明显。
- 禁止项不混入。
- Top-K 数量合理。
- 冷启动不生成伪薄弱。

这层不调用 AI，速度快，适合跑 500+ 组。

### 第二层：确定性模拟规划器

用 deterministic planner 模拟“理想 AI 会如何选任务”。

它的价值不是替代 AI，而是检查：

- 候选池是否足够支撑一个合理计划。
- 每天负载是否可排。
- 规则策略本身是否自洽。
- 哪些画像即使不调用 AI 也会失败。

如果 deterministic planner 都排不出合理计划，真实 AI 只会把问题藏进文案里。

### 第三层：真实 AI 抽样

每轮选代表画像调用 `deepseek-v4-flash`。

建议每轮：

```text
10 个画像 * 5 种模式 = 50 次调用
```

画像选择覆盖：

- 2 个冷启动。
- 2 个错题重。
- 2 个补弱明显。
- 1 个到期任务重。
- 1 个未提交练习多。
- 1 个学得多且表现好。
- 1 个异常/冲突画像。

真实 AI 评测关注：

- JSON 是否稳定。
- 理由是否真实。
- 是否遵守模式。
- 是否出现空泛建议。
- 是否超出每日负载。

### 第四层：后端 validator 回归

无论 AI 输出多漂亮，必须通过 validator。

失败示例：

- 输出不存在的题目 ID。
- 错题回收模式安排普通未开始题。
- 日期超出用户选择范围。
- 任务标题为空。
- 同一任务重复。
- 每日任务时长严重超标。

## 至少 5 轮迭代

每轮输出评测报告：

```text
round
policy_version
prompt_version
persona_count
case_count
ai_sample_count
mode_consistency
hard_violation_rate
coverage_rate
load_fit_rate
cold_start_pass_rate
explanation_grounding_rate
commitability_rate
top_failures
changes_for_next_round
```

迭代方向：

1. 第 1 轮：验证当前直觉策略。
2. 第 2 轮：调候选配比和禁止项。
3. 第 3 轮：调 prompt 和输出 schema。
4. 第 4 轮：调 validator 和 fallback。
5. 第 5 轮：固定 v1 参数并做回归。

如果第 5 轮仍有关键模式失败，继续迭代，不强行上线。

## Prompt 设计

Prompt 应该简短、结构化、少废话。

必须包含：

- 当前模式的目标。
- 允许候选类型。
- 禁止候选类型。
- 天数和每日分钟数。
- 压缩候选池。
- 输出 JSON schema。

不要包含：

- 全量题干。
- 全量历史。
- 无关页面文案。
- 让模型自由发挥的长篇背景。

## Fallback 策略

AI 超时、JSON 解析失败、validator 不通过时，不应该让用户空等。

Fallback：

1. 后端 deterministic planner 生成规则草案。
2. UI 标注“规则草案，AI 规划失败原因：xxx”。
3. 用户仍可选择性加入复习规划。
4. 失败原因写入日志和返回 payload，方便排查模型/网络/prompt 问题。

## 页面影响

第一版页面不需要大改。

只需要让 AI 规划弹窗显示更明确的状态：

- 当前模式。
- 本模式默认纳入内容。
- 被禁用的内容和原因。
- AI 使用的数据范围，例如“页面显示 Top 3，AI 使用 Top 20”。
- 生成草案来源：AI 草案 / 规则草案。
- 加入复习规划前仍可勾选。

## 验收标准

策略 v1 可用需要满足：

- 五种模式都有独立 policy。
- 至少 60 个固定画像 + 40 个扩展画像，每轮 500 组规则/模拟评测。
- 至少 5 轮迭代记录。
- 每轮真实 AI 抽样不少于 50 次，除非用户明确要求省 token 暂停。
- 错题回收模式禁止项违规率为 0。
- 新题启动冷启动通过率 >= 95%。
- 所有模式任务可执行率 >= 98%。
- JSON/validator 失败时 fallback 可用。
- 用户勾选确认后能幂等写入复习规划。

## 自查结论

本设计把“用户选择模式”作为输入，不是让 AI 自己决定最终模式。AI 只能在用户指定模式内安排日程和解释理由。

固定画像数量从最低 40 扩展到 60，并且每轮追加参数化扩展画像，避免只覆盖少量手写场景。

deterministic planner 不用于替代 AI，而用于验证后端候选池和规则策略是否足够好。它能省 token，也能提前定位“不是模型问题，而是候选池/策略问题”的失败。

后续实现应先做 mode policy 和评测 harness，再接真实 AI 调优。否则前端看起来有五种模式，实际仍可能是同一套后端逻辑。

## 2026-07-14 初始落地评测记录

本轮先落地初始方案，不把 AI 直接写入复习任务；AI 只生成草案，后端负责校验，用户勾选确认后才写入。

规则层评测：

- 固定画像：60 个。
- 模式：balanced / weak / wrong / startup / sprint。
- 组合：60 × 5 = 300 组。
- 非法任务数：0。
- deterministic planner 模式贴合均值：0.885。

真实 AI 抽样：

- 模型：deepseek-v4-flash。
- 覆盖画像：40 个。
- 组合：40 × 5 = 200 组。
- LLM 正常返回：200 / 200。
- 非法候选引用：0。
- 候选可执行率：1.0。
- 模式贴合均值：0.7476。
- 低贴合样例主要集中在 balanced 与部分 startup/sprint 场景，原因是这些模式允许混合多类候选；后端 validator 已保证不会写入不存在的题目或任务。

本轮修正：

- AI 输出中的 `review_task`、`wrong_question`、`pending_item`、`draft_attempt`、`unstarted_question` 等别名统一映射到后端候选类型。
- AI 草案项如果没有真实候选来源，会被丢弃并由 fallback 补足，不允许生成无法落地的任务。
- fallback 生成任务时保留通用 `source_id`，避免出现“复习 0 道错题”或空来源任务。
- prompt 明确要求 `item.type` 优先使用 `policy.enabled_types`，并遵守当前规划模式。
